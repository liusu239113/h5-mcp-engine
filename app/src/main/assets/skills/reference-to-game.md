# 参考图 → 1:1 还原（照着设计稿 / 截图做界面）

适用：用户丢来一张图（UI 设计稿、别人的游戏截图、自己画的草图、竞品界面），
说「照着这个做」「还原一下」「1:1 复刻」「按这张图做界面」。

**这不是「看着大概画一个」。** 用户要的是像素级接近 —— 差一点点他一眼就看出来。

---

## 0. 先纠正一个最常见的错

❌ **不要**用手写 CSS / Canvas 去「近似」画出一个好看的界面。
   手画的渐变、阴影、圆角、图标，永远跟参考图差一截，用户一看就知道不对。

✅ **正确做法**：参考图里的**图片资源要真的生成出来，再拼进界面**。
   参考图里的按钮底、面板边框、图标、角色、纹理、背景 —— 这些**本来就是图片**，
   你用代码去「模拟」它，等于重新发明一遍，而且发明得不像。

一句话：**该是图的地方就生成图，别用代码硬凑。**

---

## 1. 动手前：把参考图拆开（这一步不能省）

先用 `game_read` 或 `screenshot` 拿到参考图，然后**逐块拆**。写一份清单，别在脑子里记。

```
参考图拆解表
├─ 画布     尺寸多少？比例多少？（360×640？1080×1920？）
├─ 布局     分成几块？每块的相对位置和占比
├─ 色板     主色 / 副色 / 强调色 / 背景色 / 文字色 —— 取具体色值，不要写「深蓝」
├─ 文字     字号层级（标题/正文/说明）、字体感觉（黑体/衬线/圆体）、对齐方式
├─ 图形资源 哪些是「图」？（图标、logo、角色、纹理、装饰边框、按钮底图）
├─ 圆角/描边/阴影   具体数值感（大圆角还是直角？有没有描边？阴影软还是硬？）
└─ 状态     有没有 hover / 按下 / 选中 / 禁用 的不同样子？
```

**取色不要靠眼睛估**：用 `js_eval` 在页面里读，或从图上取。
实在要估，也写成十六进制（`#12695C`），不要写「偏绿的深色」—— 那样写代码时还得再猜一次。

---

## 2. 哪些要「生成图片」，哪些要「用代码画」

这是关键判断，**先分类再动手**：

| 参考图里的东西 | 怎么做 | 为什么 |
|---|---|---|
| 图标 / logo / 徽章 | **生成图片**（`transparent=true`） | 图标是矢量造型，代码画不像 |
| 角色 / 立绘 / 头像 | **生成图片**（`transparent=true`） | 同上，而且要有美术感 |
| 面板底 / 按钮底 / 卡片 | **生成图片**（九宫格思路） | 有纹理、渐变、描边、内阴影，CSS 难还原 |
| 背景 / 场景 / 大地图 | **生成图片**（`transparent=false`） | 是画出来的 |
| 纹理 / 纸感 / 噪点 | **生成图片**，用 repeat | 程序化噪点又慢又假 |
| 纯色块 / 分隔线 / 简单圆角 | **用代码**（CSS / Canvas） | 这些本来就该是代码，生成图反而糊 |
| 文字 | **用代码**（真文字） | 生成图里的字不可改、不可缩放、不可多语言 |
| 简单几何图形（圆、条、进度条） | **用代码** | 同上 |

**判断口诀**：
> 需要「美术造型」的 → 生成图；
> 是「排版 / 布局 / 纯色几何」的 → 用代码。

⚠️ 最容易犯的两个错：
- 把图标也用 CSS 画（结果不像）；
- 把整张 UI 一次性生成为一张大图当背景（结果文字改不了、按钮点不了、分辨率一放大就糊）。

**正确做法是「分层」**：背景图 + 面板图 + 图标图各自生成，文字和布局用代码拼上去。

## 3. 生成素材（每个组件一张，别偷懒合成一张）

调 `generate_image`（单张）或 `batch_generate_images`（一批，**推荐**，快很多）。

**铁律**：
- **图标 / 角色 / 道具 / UI 元件 → 必须传 `transparent=true`**（这是工具参数，不是 prompt 里的字）。
  只写「透明背景」四个字而没传参数，出来就是白底图 —— 这是最高频的坑。
- **背景 / 场景 / 大地图 → `transparent=false`**。
- **参考图里已经有那张图**（比如是别人的截图）→ 用 `edit_image`，
  把参考图当输入，让它照着生成；**不要**凭空重画一张不一样的。

### 拆件示例

参考图是一个 RPG 主界面，拆成这样一批：

```
batch_generate_images([
  { name: "bg_main",      prompt: "中世纪奇幻村庄背景，黄昏，暖色调，横幅构图", transparent: false },
  { name: "panel_wood",   prompt: "木质 UI 面板底，深棕，带雕花边框，无文字", transparent: true },
  { name: "btn_gold",     prompt: "金色圆角按钮底，金属质感，无文字无图标", transparent: true },
  { name: "icon_sword",   prompt: "像素风剑图标，正面，无背景", transparent: true },
  { name: "icon_shield",  prompt: "像素风盾牌图标，正面，无背景", transparent: true },
  { name: "icon_potion",  prompt: "像素风红色药水瓶图标，无背景", transparent: true }
])
```

**每张图的 prompt 要写清楚**：
1. 是什么（图标 / 面板 / 背景）；
2. 什么风格（像素 / 厚涂 / 扁平 / 拟物）；
3. 主色调（跟参考图取到的色值对齐）；
4. **明确说「无文字」「无背景」**（不写的话它经常自己加字加底）。

### 一次生成一批，别一个一个来

`batch_generate_images` 一次能出多张，比连着调十几次 `generate_image` 快得多。
**先把拆解表列完，再一次发出去。**

⚠️ 生成前告诉用户大概几张、可能消耗额度。

## 4. 拼装：把素材放对位置

素材生成后会被 materialize 到项目里（`assets/image/` 等），**直接用相对路径引用**，
不需要搬文件。

### H5 工程（DOM + CSS）

```html
<!-- 面板：把生成的图当 background -->
<div class="panel">
  <img class="icon" src="assets/image/icon_sword.png" alt="">
  <span class="label">铁剑</span>
</div>

<style>
.panel{
  /* 九宫格拉伸：生成的图不要直接拉伸，圆角和描边会变形 */
  border-image: url("assets/image/panel_wood.png") 24 fill / 24px stretch;
  padding: 16px;
  display: flex; align-items: center; gap: 8px;
}
.icon{ width: 32px; height: 32px; image-rendering: pixelated; }  /* 像素图要这个，不然糊 */
</style>
```

**九宫格（`border-image`）是还原面板的关键**：生成的图边缘有描花/圆角，
直接 `background-size: 100% 100%` 拉伸会把花纹拉变形。
`border-image` 只拉伸中间，四角保持原样 —— 这是 1:1 还原面板的正确姿势。

### Maker / UrhoX 工程

用 `urhox-libs/UI` 的 Image 组件引用生成图，**不要**用 raw NanoVG 手绘面板
（详见 `_skills/urhox-maker-handbook.md` 与 `ui-kits-guide.md`）。

## 5. 对齐参考图（这一步决定「像不像」）

拼完之后**必须**逐项核对，不要凭感觉说「差不多了」：

| 核对项 | 怎么对 |
|---|---|
| 位置 | 用 `js_eval` 读元素的实际 `getBoundingClientRect()`，跟参考图的比例对照 |
| 尺寸 | 同上，量出来比 |
| 颜色 | 读实际渲染色，跟拆解表里的色值比 |
| 字号 | 读 `getComputedStyle(el).fontSize` |
| 间距 | 量相邻元素的 gap |

**用 `game_shot` 截图，跟参考图并排比**：
1. `game_shot` 拿当前画面；
2. 把两张图放在一起看（你自己看，或让用户看）；
3. 列出「哪里不一样」；
4. 改，再截一次。

**至少两轮**。第一轮一定会有明显偏差。

---

## 6. 完成标准（缺一项都不算「还原」）

- [ ] 参考图里每个**图片资源**都真的生成出来了，不是代码凑的
- [ ] 布局比例、位置、尺寸跟参考图对得上（量过，不是估的）
- [ ] 色值取自参考图，不是「看着差不多」
- [ ] 面板用了九宫格，没有被拉伸变形
- [ ] 文字是真文字（可改、可缩放），不是图片里的字
- [ ] `game_shot` 截图跟参考图并排看过，**至少两轮**
- [ ] 控制台零报错（`game_validate`）
- [ ] 关键交互（点按钮）有反馈

---

## 7. 反例（用户会一眼看出来）

| 反例 | 为什么不行 |
|---|---|
| 用 CSS 渐变 + 手绘圆角「模拟」面板 | 跟参考图的纹理/描边完全不是一回事 |
| 整张 UI 生成为一张大图当背景 | 文字改不了、按钮点不了、放大就糊 |
| 图标用 emoji 或 CSS 画 | 造型不对，风格不统一 |
| 生成图直接 `background-size:100% 100%` | 圆角和描边被拉变形 |
| 只写 prompt「透明背景」没传 `transparent=true` | 出来是白底图 |
| 截一次图就说「已还原」 | 第一轮一定有偏差，用户一眼能看出来 |
| 尺寸用「看起来差不多」的整数 | 比例会偏，整体就不像了 |

---

## 8. 和用户确认的两件事

1. **生成素材前**：报一下要生成几张、分别是什么（可能要花额度）。
2. **完成时**：给出「参考图 vs 实现」的对比说明 —— 哪里一样、哪里做了取舍（比如字体不同）。

⚠️ 参考图如果是**别人的游戏/商业设计**，还原时要提醒用户：
可以做「参考其布局与结构」，但不要直接抄它的美术资源。
